## 문제

2026 CSE TECH WEEK 자율 이동로봇 기반 Search & Rescue 해커톤. Webots R2025a의 아파트 월드에서 TurtleBot3 Burger가 **시작점에서 출발해 빨간 사과 2개를 찾아 접근한 뒤 다시 시작점으로 돌아오는** 임무입니다.

제약이 핵심이었습니다. **지도는 주어지지 않고, GNSS·절대 위치는 쓸 수 없고**, 기본 로봇 속도를 넘길 수 없습니다. 쓸 수 있는 건 휠 엔코더, 2D LiDAR, 카메라, 나침반·자이로뿐입니다. 집 안에는 0.2 m/s로 걸어 다니는 보행자가 있어 충돌하면 감점이고, 심사 기준에는 "충분한 안전거리"가 들어 있었습니다.

## 접근

주행을 `SCAN → EXPLORE ⇄ APPROACH → RETURN → DONE` 상태 기계로 짜고, 각 단계에서 가장 아픈 문제를 하나씩 막았습니다.

- **위치 추정** — 엔코더만 믿으면 오차가 누적됩니다. LiDAR 스캔 매칭으로 x, y를 연속 보정하고, 바퀴 반지름을 실측값(0.0336 m)으로 교정했습니다. 바퀴 회전량과 나침반 각도를 비교해 **헛돌기(미끄러짐)를 감지**하면 그 구간의 주행거리를 신뢰하지 않습니다.
- **탐색** — 미탐색 경계(프론티어)를 고르고 D*로 경로를 깔되, 속도 명령은 DWA로 냅니다.
- **보행자** — 카메라로 사람을 검출해 칼만 필터로 추적하고, 예상 경로를 피해 돌아갑니다.
- **낮은 장애물** — LiDAR에 안 잡히는 바닥 물체(과일·캔)를 카메라와 YOLO로 잡아 장애물 지도에 넣었습니다.
- **목표 확인** — 색 분할로 후보를 찾고 YOLO로 사과인지 한 번 더 확인합니다.

## 결과

대회와 같은 조명 조건에서, 확정 설정으로 측정한 수치입니다.

표: 확정 설정 측정 결과

| 항목 | 결과 |
|---|---|
| 빨간 사과 | **2 / 2 방문** (같은 설정 세 번 중 두 번) |
| 위치 오차 최대 | **8.9 cm** (스캔 매칭·미끄러짐 감지를 끄면 304 cm) |
| 복귀 | 609.1초, 시작점까지 실제 **0.22 m** |
| 보행자 접촉 | 0초 |
| 바닥 물체 밀어냄 | 0 / 8 (카메라 장애물을 끄면 3 / 8) |

측정은 Supervisor로 정답 위치를 읽는 별도 스크립트가 하고, **주행 판단에는 쓰지 않습니다**. 제출은 모듈을 한 파일로 합쳐 내는데, 합친 파일과 모듈 실행의 상태 로그가 완전히 같은지 확인했습니다. 제출물에 GPS·Supervisor 흔적이 남으면 빌드 자체가 실패하게 해 뒀습니다.

## 배운 점

- 켠 것과 끈 것을 같은 월드에서 번갈아 돌려 **기여도를 따로 재는 것**이 결국 설정을 정하는 유일한 방법이었습니다. 304 cm → 8.9 cm처럼 수치가 갈리는 항목만 남기고 나머지는 껐습니다.
- 시뮬레이션이 결정적이라 해도, **같은 설정 세 번 중 두 번**이면 그대로 적어야 합니다. 한 번 잘 나온 실행을 성적으로 쓰지 않았습니다.
- 남은 약점도 재서 적었습니다. 카펫 가장자리(두께 2 cm)는 LiDAR에 안 보여 미리 피하지 못하고, 넓은 통로에서 DWA가 좌우를 번갈아 고르는 구간이 있습니다. 진단해 보니 19구간 중 15구간은 전진 후보가 100% 안전했으니, 여유가 아니라 방향 선택의 문제입니다.
