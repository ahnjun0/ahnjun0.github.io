## Problem

The 5th Inter-University Deep Learning Challenge 2026. The base model is fixed to `Qwen/Qwen2.5-3B-Instruct`; the task is reading a math problem and producing the integer answer (exact match). No external APIs or tool use, no weight merging, fine-tuning only. The question was how far a single 3B model could be pushed.

## Approach

Improving one model hit a ceiling, so I changed the design to a **cascade of three models derived from the same base**, called in stages.

1. **STAR** (LoRA r128, self-distillation on the contest train set) — generate 32 votes; if the top answer has ≥ 22 votes, commit. About 41% of questions end here.
2. **LONGCOT** (full fine-tuning, distilled from R1 long-CoT) — add 32 more votes (64 total) for unresolved questions; commit if the top-two margin is > 5 (about 46%).
3. **STAR-OLY** (LoRA r128, self-distillation on an external olympiad pool) — 32 more votes (96 total) for the remaining close calls (about 13%).

The routing condition is **vote structure only**. It never looks at the problem's topic, source, or answer, so this is not type-based routing; which stage a question reaches is determined purely by the generations. Stage 2 uses a model with a *different reasoning regime* because, on close questions, mixing votes from models that make different mistakes flipped more answers than adding votes from the same model.

## Result

- Leaderboard **0.80385 (668 / 831)**. The third stage's contribution was isolated with a paired test that re-assembled the control from the same generation batch (668 vs. 665).
- I reported labeling errors on the leaderboard to the organizers, which led to the **leaderboard being re-scored from 1,000 to 831 items** and every participant being re-evaluated. A second batch of 14 reports followed.
- I documented four rule grey areas (checkpoint averaging, scope of teacher use for distillation, etc.) myself, and shipped verification scripts showing the inference path makes no network calls.
- Final results are pending.

## What I learned

- A *different* model beats a *bigger* model on close questions. Measuring the capacity ladder (8B → 14B), a 1.75× increase bought exactly +1 question.
- Following the rules and *proving* you followed them are separate jobs. I spent the last two days organizing the repository so a judge could verify it with a single grep.
